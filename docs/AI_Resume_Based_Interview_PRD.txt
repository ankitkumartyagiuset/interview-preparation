PRODUCT REQUIREMENTS DOCUMENTAI Resume-Based Interview & Skill Gap Platform
Version 1.0  |  Product Type: AI-powered CareerTech / EdTechPrimary Users: Students, Freshers, Job Seekers, Colleges, Recruiters

1. Product Overview
The platform accepts a candidate's resume, analyses skills, education, projects, certifications and experience, and creates a personalised interview. The AI conducts HR, technical, project and role-specific questions, adapts follow-up questions based on answers, evaluates performance, identifies skill gaps, and generates a personalised improvement roadmap and interview-readiness report.
2. Problem Statement
Most interview-preparation platforms use generic question sets and do not reflect the candidate's actual resume or target role. Candidates therefore struggle to understand whether they can defend the claims on their resume, what an interviewer is likely to ask, which skills are weak, and what they should improve before a real interview.
The product solves this by creating a closed loop: Resume → Personalised Interview → Evidence-based Evaluation → Skill Gap Analysis → Improvement Roadmap → Reassessment.
3. Product Goals
Automatically extract a structured candidate profile from a resume.
Generate a personalised interview based on resume evidence and target job role.
Conduct adaptive HR, technical, project and behavioural interviews.
Evaluate answers using transparent, structured rubrics.
Detect gaps between claimed and demonstrated skills.
Provide actionable learning and practice recommendations.
Track readiness and improvement across multiple interview attempts.
Provide a detailed final report without making an automated hiring decision.

Resume Evidence Model
The system should distinguish between information explicitly present in the resume and information inferred by AI. Claims such as 'Expert in Python' should be treated as claims to validate rather than facts.
7. Resume Claim Verification
The AI should test important resume claims through targeted questions. Example: if a candidate claims expert Python knowledge, the system may ask about decorators, generators, concurrency or a relevant production use case. The report can show claimed level versus demonstrated level with a confidence indicator.

11. Adaptive Difficulty
Difficulty should change according to demonstrated performance. Strong answers can trigger deeper questions; weak answers can trigger clarification, conceptual questions or a lower difficulty level. The goal is to estimate competence rather than simply maximise difficulty.
12. Dynamic Follow-up Engine
The interview should not behave like a fixed questionnaire. Follow-up questions must use the candidate's previous answer and resume evidence. Example: a Django project claim can lead from architecture → scaling → caching → database bottlenecks → production debugging.
13. Voice Interview — Future Module
Voice mode can use Speech-to-Text for candidate answers and Text-to-Speech for AI questions. Evaluation should focus on answer content and relevant communication criteria, not accent or regional pronunciation.

25. Recommended Technical Architecture
For an initial production-oriented implementation, use a web frontend with a Python API backend, a relational database, secure object storage for resumes, Redis for caching/queues, background workers for long-running jobs, and an LLM service behind a controlled AI orchestration layer.
Frontend: HTML, CSS, JavaScript, Bootstrap/jQuery for the initial version.
Backend: Python + FastAPI for API-first architecture; Django + DRF is an alternative when the project needs a heavier built-in admin ecosystem.
Database: PostgreSQL.
Cache / queue: Redis.
Background processing: Celery or an equivalent worker system.
Object storage: private bucket/storage for resumes and reports.
AI layer: separate services/prompts for extraction, interview planning, question generation, evaluation, skill-gap analysis and roadmap generation.

Restrict who can access candidate data.

Minimise sensitive/personal attributes in AI evaluation.
Provide appropriate consent and privacy notices.
30. Bias & Fairness Controls
The evaluation pipeline should not use gender, religion, caste, age, accent, location, college prestige or other irrelevant personal characteristics as competence signals. Scoring should be based on job-relevant evidence such as technical correctness, reasoning, relevant experience and answer quality. Human review should remain available for high-impact hiring workflows.
31. Performance & Scalability
Keep normal API operations low-latency.
Use asynchronous processing for resume parsing and long AI jobs.
Stream interview responses where supported.
Cache safe reusable data such as skill taxonomies and static question metadata.
Scale backend instances horizontally behind a load balancer.
Use connection pooling and indexed database queries.
Monitor AI latency, token usage, failures and queue depth.
Do not promise a fixed sub-500 ms latency for LLM-generated responses; model/provider latency is variable. Set separate SLOs for ordinary APIs and AI operations.

36. Major Product Risks & Mitigations
Risk
Mitigation
Incorrect AI evaluation
Structured rubrics, calibration datasets, deterministic checks where possible, human review.
Resume hallucination
Separate explicit resume evidence from AI inference.
Bias
Remove irrelevant personal attributes from scoring and audit outcomes.
High AI cost
Model routing, caching, batching and usage limits.
Data leakage
Private storage, access controls, encryption and secure deletion.
Over-reliance on a readiness score
Show evidence and feedback; clearly label score as an assessment indicator.
37. Product Vision
The long-term product should become a continuous career-readiness engine rather than a simple chatbot: Resume → Job Match → Adaptive Interview → Evidence-based Evaluation → Skill Gap → Personalised Learning → Reassessment → Measurable Progress.
38. One-line Product Definition
An AI-powered career platform that transforms a candidate's resume into a personalised interview, evaluates job-relevant readiness, identifies skill gaps, and provides a data-driven improvement roadmap.
